# Принципы проекта (инварианты)

Неизменяемые принципы, ограничивающие все спеки и реализацию. Если спека им противоречит —
меняется спека, а не принцип.

1. **Информационная роль, human-in-the-loop.**
   Система не выносит вердиктов и не наказывает. Она готовит для преподавателей отчёты о
   подозрительных посылках; финальное суждение — за человеком (глазами).

2. **Низкий false-positive важнее recall.**
   Ошибочно заподозрить школьника хуже, чем пропустить случай. При сомнении — не поднимать шум.

3. **Объяснимость.**
   Каждый сигнал сопровождается человекочитаемым доказательством (`Evidence`), а не только числом.
   «Чёрный ящик» без обоснования неприемлем.

4. **Абстракция от judge-системы.**
   Детекторы работают только с каноническим форматом (`domain.Submission`). Любой внешний формат
   (ejudge, Codeforces, …) транслируется в него импортером ДО аналитики.

5. **Модульность детекторов.**
   Новый детектор/инструмент/источник добавляется без правки ядра (новый юнит + селектор +
   детектор + регистрация стадии).

6. **Аудируемость.**
   Детерминированные детекторы воспроизводимы. AI-детекторы недетерминированы — для них фиксируем
   вход и полученный вывод и архивируем отчёт (аудируемость вместо побитового детерминизма).

## Контекст (для справки)
Летняя компьютерная школа, задачи формата ICPC, 300+ участников, удалённая сдача. Данные —
только submission-level (машины участников недоступны). Режим — гибрид (онлайн-сбор + разбор
после тура). Полные требования: [requirements.md](requirements.md).

# SDD-процесс (spec-driven development)

Лёгкий кастомный SDD: разработку ведём от спецификаций к коду. Внешнего тулинга нет.

## Артефакты
- [../principles.md](../principles.md) — инварианты проекта (ограничивают все спеки).
- [../requirements.md](../requirements.md) — общие функциональные/нефункциональные требования (вход).
- `specs/NNN-<slug>/` — инкремент:
  - `spec.md` — **ЧТО и ЗАЧЕМ**: user stories, acceptance criteria, scope in/out. Без технологий.
  - `design.md` — **КАК**: архитектура, интерфейсы, алгоритмы, ADR-заметки.
  - `tasks.md` — упорядоченные задачи реализации с критериями приёмки.

## Поток
```
requirements.md ─┐
principles.md  ──┼─→ spec.md ─→ design.md ─→ tasks.md ─→ код
```

## Правила
- Нумерация инкрементов: `001`, `002`, … (по порядку).
- Реализация идёт **step-by-step под контролем**: пакет за пакетом, с локальной проверкой и ревью
  перед следующим шагом.
- Меняются требования → правим `spec.md`, затем `design.md`, затем `tasks.md`. Код — следом.

## Инкременты
- [001-walking-skeleton](001-walking-skeleton/) — тонкий вертикальный срез end-to-end (готов).
- [002-ejudge-import](002-ejudge-import/) — реальный импорт из ejudge по HTTP API (готов).
- [003-jplag-detector](003-jplag-detector/) — первый реальный детектор списывания, обёртка JPlag (готов).
- [004-html-report](004-html-report/) — интерактивный HTML-отчёт (карточки находок, side-by-side
  подсветка совпадений, фильтр по виду сигнала/score) поверх JSON-отчёта (спланировано).
- [005-multi-contest](005-multi-contest/) — `contests: []string` + `default_type` в `run.yaml`
  (несколько контестов за прогон), `domain.Subject` как sum-type с обязательным `Contest`
  (готов).
- [006-web-server](006-web-server/) — веб-сервис (Echo + JWT-защищённый REST поверх `Pipeline`)
  и React-фронт (`scainer-front/`) взамен статического HTML-отчёта; CLI `analyze`/`eval`
  остаётся, добавляется подкоманда `serve` (готов).
- [007-teacher-workspace](007-teacher-workspace/) — параллели как группировка контестов, слитая
  страница контеста+находок, редактирование списка контестов и политики анализа (исключение задач)
  прямо через UI; `run.yaml` переходит на единую декларацию контеста (в работе).

Планируется (без номера, пока не начато): переработка `eval`, AI-подсистема (реализация
AI-детектора с `Detector.AI()`, каркас под него уже в 004), устойчивость `Stage.Run` к ошибке
одного детектора (NFR-8), config-driven выбор детекторов.
